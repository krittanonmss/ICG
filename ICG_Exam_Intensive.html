01 · Material แบบที่ต้องแยกให้ออก

นิยาม · เปรียบเทียบ · เลือกใช้ · กับดัก

Material คือชุดข้อมูลและคำสั่งที่บอกว่าผิวของวัตถุควรแสดงผลอย่างไร เช่น สีพื้นผิว การตอบสนองต่อแสง ความมัน ความหยาบ และ texture ส่วน Shader คือโปรแกรมที่ประมวลผลข้อมูลใน rendering pipeline วัสดุสำเร็จรูปของ Three.js ใช้ shader ภายในอยู่แล้ว ไม่จำเป็นต้องเขียน GLSL เองทุกครั้ง

Materialแสงและหน้าตาตัวแปรเด่นจำใช้ตอบสอบ
MeshBasicMaterial / Unlitสีไม่เปลี่ยนตามแสงในฉาก ไม่มีการคำนวณแสงผิวแบบ Lambert/Phongcolor, mapใช้กับสีที่ต้องการคงที่; ไม่มีไฟก็ยังเห็นสี
MeshLambertMaterialDiffuse แบบผิวด้าน ไม่มี specular highlight ในโมเดล Lambertcolorความสว่างขึ้นกับมุม N กับ L; ใน Three.js วัสดุนี้ใช้การคำนวณแสงแบบต่อ vertex
MeshPhongMaterialDiffuse + specular พร้อม ambient contribution ในโมเดลแสงcolor, specular, shininessเหมาะกับผิวมันเชิงประมาณ; shininess สูงทำให้ไฮไลต์แคบลง
MeshStandardMaterial / PBRจำลองการสะท้อนที่อิงฟิสิกส์มากขึ้น ใช้ metalness/roughnesscolor, metalness, roughnessโลหะเรียบ: metalness สูง roughness ต่ำ; environment ช่วยให้เห็นการสะท้อน
ShaderMaterialผู้เขียนกำหนด Vertex/Fragment เองuniforms, vertexShader, fragmentShaderไม่ได้รับโมเดล Lambert/Phong โดยอัตโนมัติ ต้องเขียนหรือประกอบระบบแสงเอง

PBR: แยก metalness กับ roughness

  • metalness 0 = อโลหะ, 1 = โลหะ ไม่ใช่ตัวควบคุมความขรุขระ โดยวัสดุเนื้อเดียวมักเลือกใกล้ 0 หรือ 1 ค่ากลางอาจใช้กับการผสม
  • roughness 0 = เรียบ ไฮไลต์/ภาพสะท้อนคม; 1 = หยาบ ไฮไลต์/ภาพสะท้อนกระจาย ความหยาบสูงไม่ใช่คำสั่ง “ไม่รับแสง”
  • base color คือสีฐาน; การตีความใน PBR โลหะกับอโลหะแตกต่างกัน ไม่ควรสรุปว่าทุกวัสดุมี diffuse เท่ากัน
  • วัตถุโลหะอาจดูมืดถ้าไม่มีสภาพแวดล้อมหรือแหล่งแสงให้สะท้อน การเพิ่ม metalness ไม่ได้สร้างความสว่างเอง
const matte = new THREE.MeshLambertMaterial({color: 0x3b82f6});
const glossy = new THREE.MeshPhongMaterial({
  color: 0x3b82f6, specular: 0xffffff, shininess: 80
});
const metal = new THREE.MeshStandardMaterial({
  color: 0xffffff, metalness: 1.0, roughness: 0.1
});
กับดัก: Phong มีไฮไลต์ไม่ได้แปลว่าเป็น PBR • BasicMaterial ไม่ตอบสนองต่อไฟแต่ยังถูกบังได้จาก depth test • คำว่า Phong reflection model (สมการแสง) กับ Phong shading (การ interpolate normal แล้วคำนวณแสงต่อ fragment) เป็นคนละแนวคิด

คำตอบสั้นที่ใช้เขียนสอบ

“Lambert คำนวณ diffuse ตามมุมระหว่าง normal กับทิศไปหาแสง ส่วน Phong เพิ่ม specular ซึ่งขึ้นกับทิศผู้มองด้วย ขณะที่ Standard เป็น PBR โดยใช้ metalness และ roughness ควบคุมลักษณะการสะท้อน และ Basic ไม่คำนวณการตอบสนองต่อแสงในฉาก”

02 · Shader, ตัวแปร และพิกัด

เข้าใจข้อมูลไหลไปไหน แล้วอ่านโค้ดให้เป็น

Attributes → Vertex Shader → Rasterization & interpolation → Fragment Shader → Depth / blending → ภาพ

Vertex Shader ทำงานต่อ vertex รับข้อมูล geometry แล้วคำนวณตำแหน่งใน clip space ผ่าน gl_Position รวมถึงส่งข้อมูลให้ fragment stage ได้ ส่วน Fragment Shader ทำงานกับ fragment ที่เกิดจาก rasterization เพื่อคำนวณสีและ alpha; fragment ยังอาจไม่กลายเป็นพิกเซลสุดท้ายหากไม่ผ่าน depth test หรือถูก discard

ข้อมูลใครส่งให้ใครตัวอย่างจุดออกสอบ
attributegeometry → vertex shader; ค่าแยกแต่ละ vertexposition: vec3, normal: vec3, uv: vec2ตำแหน่ง/normal มักอยู่ local space; UV ใช้อ้างอิง texture
uniformโปรแกรมภายนอก → shader; ใช้ค่าเดียวกันในการ draw นั้นuTime, uLightDir, uTextureอัปเดตระหว่างเฟรมได้ คำว่า uniform ไม่ได้แปลว่าห้ามเปลี่ยนตลอดโปรแกรม
varyingvertex shader เขียน → rasterizer interpolate → fragment shader อ่านvUv, vNormalค่าที่ fragment รับมักเป็นค่าที่ interpolate มา ต้อง normalize normal อีกครั้ง
gl_Positionผลลัพธ์ของ vertex shadervec4 clipPositionยังเป็น clip space ก่อน perspective divide
gl_FragColorผลลัพธ์สีแบบ GLSL ES 1.00 ในตัวอย่างเรียนvec4(rgb, alpha)GLSL ES 3.00 ใช้ output ที่ประกาศเอง; อ่านตามรูปแบบที่โจทย์ให้

เมทริกซ์: ท่องลำดับและอธิบายความหมาย

clip = P × V × M × vec4(position, 1.0)

อ่านการคูณจาก ขวาไปซ้าย: M วางจาก Object → World; V เปลี่ยน World → View; P เปลี่ยน View → Clip จากนั้นหารด้วย w เป็น NDC และแปลง viewport ไปหน้าจอ

ชื่อชนิดความหมาย
modelMatrixmat4Object → World
viewMatrixmat4World → View (พิกัดกล้อง)
projectionMatrixmat4View → Clip
modelViewMatrixmat4viewMatrix × modelMatrix
normalMatrixmat3inverse-transpose ของส่วน 3×3 ของ modelViewMatrix; แปลง normal ไป View space
cameraPositionvec3ตำแหน่งกล้องใน World space; เป็นเวกเตอร์ ไม่ใช่เมทริกซ์
กฎเหล็กเรื่อง space: เวกเตอร์ที่นำมา dot ต้องอยู่ใน coordinate space เดียวกัน ถ้า N มาจาก normalMatrix จะเป็น View space แต่ L เป็น World space ต้องแปลง L ให้ตรงกันก่อน ห้ามใช้ cameraPosition − ตำแหน่งแบบ View โดยตรง

Vertex displacement ที่ต้องอ่านออก

uniform float uTime;
varying vec2 vUv;
void main() {
  vUv = uv;
  vec3 pos = position;
  pos += normalize(normal) * sin(pos.x * 4.0 + uTime * 2.0) * 0.2;
  gl_Position = projectionMatrix * modelViewMatrix * vec4(pos, 1.0);
}
  • normalize(normal): เลื่อนตามแนวตั้งฉากผิวใน local space ไม่จำเป็นต้องตรงแกน y ของโลก
  • 0.2: amplitude ระยะเลื่อนสูงสุด ±0.2 หน่วย เมื่อ normal เป็นหน่วย
  • 4.0: spatial angular frequency; เพิ่มแล้วคลื่นถี่ขึ้นตาม x ความยาวคลื่นคือ 2π/4
  • 2.0 ที่คูณ uTime: angular speed ถ้าเวลาเป็นวินาที คาบคือ 2π/2 = π วินาที
  • การเลื่อน vertex ไม่ได้สร้าง vertex ใหม่ Mesh ต้องมี subdivision เพียงพอจึงเห็นโค้งละเอียด และ normal เดิมอาจไม่ตรงผิวใหม่ หากต้องการแสงแม่นยำต้องปรับ normal ตามการ deform

UV กับ texture

texture2D(uTexture, uv).r อ่านช่องสีแดงที่พิกัด UV ถ้าใช้เป็น height map ค่าสูงทำให้ยกพื้นมากขึ้นตามสเกลที่คูณ การอ่าน texture เพื่อเปลี่ยนสีใน fragment ไม่ทำให้ silhouette เปลี่ยน แต่การย้าย vertex สามารถเปลี่ยนรูปทรงและ silhouette ได้

โค้ดคู่พื้นฐานสำหรับจำโครง

// Vertex (รูปแบบ GLSL ES 1.00 ตามสไลด์)
varying vec2 vUv;
void main() {
  vUv = uv;
  gl_Position = projectionMatrix * modelViewMatrix * vec4(position, 1.0);
}
// Fragment
uniform sampler2D uTexture;
varying vec2 vUv;
void main() {
  vec3 base = texture2D(uTexture, vUv).rgb;
  gl_FragColor = vec4(base, 1.0);
}

หมายเหตุสำหรับอ่านโค้ด: built-in attributes และ uniforms บางตัวถูกจัดเตรียมโดย Three.js ShaderMaterial โค้ดนี้เป็นตัวอย่างโครง shader ไม่ใช่หน้า Three.js ที่รันได้ทั้งฉาก

03 · GLSL + Lambert + Phong + Cel

หัวใจของโจทย์แทนค่าและจับผิดสูตร

ฟังก์ชัน GLSL ที่ต้องทำด้วยมือได้

ฟังก์ชันความหมายตัวอย่างและคำตอบ
max(a,b) / min(a,b)เลือกมากสุด / น้อยสุดmax(−0.3,0)=0; min(0.7,0.5)=0.5
clamp(x,lo,hi)บีบเข้าช่วงclamp(1.4,0,1)=1; clamp(−0.2,0,1)=0
pow(x,y)ยกกำลังpow(0.5,4)=0.0625; กันฐานลบก่อนทำ specular
abs / signค่าสัมบูรณ์ / เครื่องหมาย −1,0,1abs(−0.6)=0.6; sign(0)=0
floor / ceilปัดลง / ปัดขึ้นfloor(−1.2)=−2; ceil(−1.2)=−1
fract(x)x − floor(x)fract(2.75)=0.75; fract(−1.2)=0.8
mod(x,y)x − y × floor(x/y)mod(−1,3)=2; ต่างจาก remainder บางภาษา
step(edge,x)0 เมื่อ x < edge; นอกนั้น 1step(0.5,0.49)=0; step(0.5,0.5)=1
smoothstep(e0,e1,x)เปลี่ยน 0 → 1 แบบเรียบในช่วง e0 ถึง e1ที่กึ่งกลางช่วงได้ 0.5; ใช้ e0 < e1
dot(a,b)a.x×b.x + a.y×b.y + a.z×b.zdot((1,2,3),(4,0,−1))=1
normalize(v)v / length(v)normalize((0,3,4))=(0,0.6,0.8); ไม่ใช้กับเวกเตอร์ศูนย์
reflect(I,N)I − 2 dot(N,I)N โดย N เป็นหน่วยI ชี้เข้าหาผิว; หาก L ชี้ไปหาไฟ ใช้ reflect(−L,N)

Dot product = อ่านมุมของแสง

a · b = |a||b| cos θ → ถ้า normalize ทั้งคู่: N · L = cos θ

N คือ normal ชี้ออกจากผิว; L คือทิศ จากผิวไปหาไฟ เวกเตอร์ทิศทางหา point light คำนวณได้จาก normalize(lightPosition - surfacePosition) เมื่อกำหนด space ตรงกัน

มุม N กับ LN · L เมื่อเป็น unitผล diffuse
0°1รับแสงตรงที่สุด
60°0.5ครึ่งหนึ่งของค่าสูงสุด
90°0แสงเฉียดผิว
120°−0.5clamp ด้วย max → 0 ไม่ได้ความสว่างติดลบ

Lambert: diffuse

Id = kd Ip max(N · L, 0)

kd คือสัมประสิทธิ์ diffuse; Ip คือความเข้มไฟตามนิยามโจทย์ ถ้าเป็นสี RGB คิดแต่ละ channel แยกกัน ไม่มี V ในสูตร จึงไม่ขึ้นกับทิศกล้องเมื่อผิวและไฟคงที่ โจทย์อาจแยก attenuation ออกมาต่างหาก อย่าเพิ่มเองถ้าไม่ได้กำหนด

Phong: ambient + diffuse + specular

I = kaIa + kdIpmax(N·L,0) + ksIp[max(R·V,0)]n
  • V = normalize(cameraPosition − surfacePosition) ชี้จากผิวไปหากล้อง
  • R = reflect(−L,N) เป็นทิศสะท้อน; N, L, V เป็น unit และอยู่ space เดียวกัน
  • n / shininess สูง → ไฮไลต์แคบและคมขึ้น สำหรับค่า 0 < R·V < 1 ค่าที่ยกกำลังสูงจะเล็กลง
  • Ambient เป็นแสงพื้นโดยประมาณ ไม่ขึ้นกับมุม N·L; ไม่ควรบอกว่า ambient สร้างเงาทิศทางได้
  • ในโมเดลผิวด้านเดียว โดยปกติควรปิด specular เมื่อ N·L ≤ 0 เพื่อไม่ให้ด้านหลังไฟมีไฮไลต์
// ทุกเวกเตอร์ใน View space; uLightDirView ชี้จากผิวไปหาแสง
vec3 N = normalize(vNormalView);
vec3 L = normalize(uLightDirView);
vec3 V = normalize(-vPositionView); // กล้องอยู่ origin ใน View space
float ndl = max(dot(N, L), 0.0);
vec3 R = reflect(-L, N);
float spec = 0.0;
if (ndl > 0.0) {
  spec = pow(max(dot(R, V), 0.0), uShininess);
}
vec3 color = uAmbient * base + uLightColor * (base * ndl + uKs * spec);
gl_FragColor = vec4(color, 1.0);

Cel shading: ทำความสว่างเป็นขั้น

Cel ใช้การ quantize แทนไล่ระดับต่อเนื่อง เช่น floor(d * levels) / levels แล้วอาจ threshold specular ด้วย step หรือ smoothstep ส่วนเส้น outline เป็นอีกองค์ประกอบหนึ่ง ไม่ใช่เงื่อนไขว่าต้องมีจึงเป็น cel

float d = max(dot(N, L), 0.0);
float q = floor(d * 3.0) / 3.0;
// d=0.70 -> floor(2.10)/3 = 2/3
// d=1.00 -> 1.00 (จุดปลายให้ค่าระดับพิเศษ)
float sharpHighlight = step(0.5, specular);
จุดที่ต้องอ่านสไลด์อย่างระวัง: โค้ดตัวอย่าง cel ในสไลด์เขียน clamp(pow(dot(R,V),4.0),0,1) การ clamp หลัง pow ไม่ได้กันฐานติดลบ ควรใช้ pow(max(dot(R,V),0.0),4.0) ก่อน ค่าฐานลบไม่ใช่โดเมนที่รับประกันของ GLSL pow และการยกกำลังคู่ยังทำให้ด้านผิดทิศดูสว่างได้หากคิดเชิงคณิตศาสตร์ตรง ๆ

Outline แบบ inverted hull: ทำ mesh อีกชั้น ขยายตาม normal เช่น pos += normal * 0.03 ใช้สีเข้มและ THREE.BackSide ให้เห็นขอบชั้นหลัง ความหนาบนจออาจเปลี่ยนตามระยะและสเกล การ deform ของ outline ควรสอดคล้องกับ mesh หลัก

04 · Object Picking + LERP

จากตำแหน่งเมาส์สู่การเลือกวัตถุ แล้วเลื่อนกล้อง

จำเป็นลำดับ 5 ขั้น

  1. รับ clientX/clientY แล้วลบตำแหน่งมุมซ้ายบน canvas
  2. แปลง local pixel เป็น NDC ช่วง −1 ถึง +1 โดยกลับแกน y
  3. raycaster.setFromCamera(pointer, camera) สร้าง ray ตามกล้อง
  4. intersectObjects(pickables, ...) หาจุดตัดกับวัตถุที่อนุญาตให้เลือก
  5. ตรวจว่ามี hit แล้วเลือกอันใกล้สุด ผล intersection เรียงตามระยะใกล้ไปไกล จึงเริ่มจาก hits[0]
xNDC = 2(px / w) − 1
yNDC = 1 − 2(py / h)

px, py เป็นพิกัดภายใน canvas; w, h เป็นขนาด canvas ในหน่วย CSS pixel ที่ใช้ตรงกับ client coordinates มุมซ้ายบนเป็น (−1,+1), กึ่งกลาง (0,0), มุมขวาล่าง (+1,−1) อย่าใช้ window.innerWidth ถ้า canvas ไม่ได้เต็มหน้าต่าง

const pointer = new THREE.Vector2();
const raycaster = new THREE.Raycaster();
function onPick(e) {
  const r = renderer.domElement.getBoundingClientRect();
  pointer.x = ((e.clientX - r.left) / r.width) * 2 - 1;
  pointer.y = 1 - ((e.clientY - r.top) / r.height) * 2;
  raycaster.setFromCamera(pointer, camera);
  const hits = raycaster.intersectObjects(pickables, true);
  if (hits.length === 0) return;
  const selected = hits[0].object;
  console.log(selected.name);
}
renderer.domElement.addEventListener('pointerdown', onPick);

true หมายถึงตรวจลูกใน hierarchy ด้วย ส่วน false ตรวจเฉพาะวัตถุในรายการนั้น ถ้า hit เป็น mesh ลูกและต้องการเลือกทั้งกลุ่ม ต้องหา parent/ข้อมูลอ้างอิงที่เหมาะสมเอง ไม่ใช่ถือว่า hits[0].object เป็น root เสมอ

Ray แบบคณิตศาสตร์

P(t) = O + tD, t ≥ 0

O = จุดกำเนิด, D = ทิศทาง ถ้า D เป็น unit, t เป็นระยะทาง การเลือกผิวหน้าสุดใช้ค่า t ที่ไม่ติดลบและต่ำสุด ใน perspective ray โดยทั่วไปออกจากกล้อง ส่วน orthographic ray แต่ละตำแหน่งขนานกันและจุดเริ่มเปลี่ยนตาม pointer

LERP = เปลี่ยนค่าตามสัดส่วน

lerp(a,b,t) = a + (b−a)t = (1−t)a + tb
  • t=0 → a; t=1 → b; t=0.5 → กึ่งกลาง; นอกช่วง [0,1] เป็น extrapolation
  • ทำกับเวกเตอร์โดยคำนวณทีละแกน เช่น A=(0,2,4), B=(10,6,0), t=.25 → (2.5,3,3)
  • camera.position.lerp(target, 0.1) ทุกเฟรมใช้ ตำแหน่งปัจจุบัน เป็น a จึงเข้าใกล้เป้าหมายแบบ exponential ไม่ใช่เดินทางความเร็วคงที่หรือถึงปลายพอดีใน 10 เฟรม
  • ถ้าต้องการเดินทางใน T วินาที ให้เก็บ start ครั้งเดียว แล้วใช้ t=clamp(elapsed/T,0,1) กับ start/end เดิม
// แบบกำหนดระยะเวลา: start ต้องบันทึกก่อนเริ่ม ไม่เปลี่ยนทุกเฟรม
const t = Math.min(elapsed / duration, 1);
camera.position.lerpVectors(start, target, t);
// แบบค่อย ๆ ตาม: alpha คำนวณจาก deltaTime ลดการขึ้นกับ frame rate
const alpha = 1 - Math.exp(-speed * deltaTime);
camera.position.lerp(target, alpha);
เมื่อกล้องเลื่อนไปยังวัตถุ อย่าลืมจุดที่กล้องมอง: position คือจุดอยู่ของกล้อง ส่วน lookAt หรือ target ของ controls คือเป้าสายตา การเปลี่ยน position อย่างเดียวไม่รับประกันว่าวัตถุจะอยู่กลางภาพ

05 · Animation, Bezier และ Easing

ต้องดูกราฟแล้วอธิบายการเคลื่อนไหวได้

คำความหมายและการใช้งาน
Keyframeบันทึกค่าคุณสมบัติ ณ เวลา/เฟรมที่กำหนด เช่น rotation ของบานประตู ไม่ได้จำเป็นต้องบันทึกทุกเฟรม
Timelineแกนเวลา ใช้เลื่อนเฟรมและควบคุมการเล่น
Dope Sheetเห็นตำแหน่งและการกระจายของ keyframes หลาย channel เหมาะกับย้าย/ปรับ timing
Graph Editor / F-Curveกราฟค่าคุณสมบัติเทียบเวลา คุม interpolation/handle และอ่านความเร็วจากความชัน
Actionชุดข้อมูล animation ที่รวม channels และ keyframes เช่น DoorOpen / DoorClose
Interpolationวิธีคำนวณค่าระหว่าง keyframes เช่น Constant, Linear, Bezier
Easingการจัดความก้าวหน้าตามเวลาให้ช้า/เร็วช่วงใดช่วงหนึ่ง เช่น ease-in, ease-out

Interpolation ที่ออกเปรียบเทียบ

ชนิดกราฟค่า–เวลาสิ่งที่เห็น
Constantเส้นนอนแล้วกระโดดคงค่าเดิมจนถึง keyframe ถัดไป เหมาะกับ pose หรือสวิตช์ที่ต้องเปลี่ยนทันที
Linearเส้นตรงระหว่างจุดอัตราเปลี่ยนค่าคงที่ในแต่ละช่วง แต่เปลี่ยนความเร็วทันทีตรงรอยต่อได้
Bezierเส้นโค้งตาม handles/control pointsควบคุมความชันเข้าออก อาจ overshoot ได้ถ้าคุม handles แบบนั้น
Sinusoidal / Cubic / Quinticโค้งตามตระกูลฟังก์ชันเลือกโพรไฟล์การเปลี่ยนค่า แต่ต้องดู in/out เพิ่มว่าเร่งช่วงไหน
Back / Bounce / Elasticเกินเป้า / เด้ง / สั่นBack ถอยหรือเลยเป้า; Bounce เด้งกลับ; Elastic สั่นรอบปลายทาง

อ่านกราฟค่า–เวลา: ความชันสำคัญกว่าความสูง

แกนนอน = เวลา; แกนตั้ง = ค่าคุณสมบัติ ความชันคืออัตราเปลี่ยนค่า เส้นชันขึ้นมากแปลว่าเพิ่มค่าเร็ว เส้นลาดลงแปลว่าค่าลดลง เส้นราบแปลว่าค่าแทบไม่เปลี่ยน ค่าสูงไม่จำเป็นต้องเร็ว และถ้ากราฟเป็น rotation ความชันคืออัตราหมุน ไม่ใช่ความเร็วเชิงเส้น

Ease In

เริ่มช้า → เร็วขึ้น ตัวอย่าง e(t)=t² ความชันเริ่ม 0

Ease Out

เริ่มเร็ว → ช้าลง ตัวอย่าง e(t)=1−(1−t)²

Ease InOut

ช้า → เร็ว → ช้า ตัวอย่าง e(t)=3t²−2t³

กราฟตัวอย่างข้างบนเป็นค่าที่เพิ่มตามเวลา ถ้าค่าปลายทางต่ำกว่าเริ่มต้น กราฟจะลดลง แต่ยังดู “ขนาดความชัน” ว่าช่วงใดเปลี่ยนเร็ว การนำ easing ไปใช้คือ value = lerp(start, end, e(t))

Bezier: จำนวนจุดกับดีกรี

Linear (2 จุด): B(t) = (1−t)P₀ + tP₁
Quadratic (3 จุด): B(t) = (1−t)²P₀ + 2(1−t)tP₁ + t²P₂
Cubic (4 จุด): B(t) = (1−t)³P₀ + 3(1−t)²tP₁ + 3(1−t)t²P₂ + t³P₃

โดยทั่วไป degree n ใช้ n+1 control points; จุดต้นและปลายอยู่บนเส้นโค้ง แต่จุดควบคุมกลางไม่จำเป็นต้องอยู่บนเส้น Cubic ใช้ P₁ คุมทิศเข้าออกจาก P₀ และ P₂ คุมทิศก่อนถึง P₃ การกระจาย t เท่ากันไม่ได้รับประกันความเร็วคงที่ตามระยะทางบนเส้นโค้ง

เฟรม → เวลา และตัวอย่างบานประตู

ที่ 24 fps จาก frame 1 ไป frame 25 ห่างกัน 24 เฟรมจึงใช้เวลา 1 วินาที (นับระยะห่าง ไม่ใช่จำนวนเฟรมแบบรวมปลาย) ถ้าประตูเปิด 0° → 90° ด้วย linear ใน 2 วินาที ที่เวลา 0.5 วินาทีจะได้ t=.25 และมุม 22.5° หากใช้ ease-in t² จะได้ 90×.0625=5.625°

ประตูหมุนผิดแบบทั้งบานไหลวน มักต้องตรวจ pivot/origin ว่าอยู่ขอบบานตรงบานพับ ไม่ใช่แก้ interpolation อย่างเดียว

06 · แสง เงา กล้อง และฉาก

ส่วนเสริมจากสไลด์ เพื่อทำโจทย์ประยุกต์

แสงลักษณะจำเปรียบเทียบ
PointLightจุดกำเนิดเดียว ปล่อยทุกทิศทางเหมือนหลอดไฟ; ทิศ L ต่างกันตามตำแหน่งผิว
SpotLightไฟจากตำแหน่งหนึ่งออกเป็นกรวย มี targetangle กำหนดมุมกรวย; ใช้ castShadow ได้
DirectionalLightทิศทางแสงขนานโดยประมาณ เหมือนแสงอาทิตย์ไกลมากตำแหน่งและ target กำหนดทิศ; ไม่ใช่แหล่งไฟแบบจุด
RectAreaLightพื้นที่สี่เหลี่ยมปล่อยแสงด้านเดียวในตัวอย่าง Three.js ใช้กับวัสดุ PBR Standard/Physical; ไม่ควรเหมารวมว่า castShadow ได้เหมือนทุกชนิด
AmbientLightเพิ่มแสงทั่วฉากแบบไม่มีทิศทางสร้างเงาแบบมีทิศไม่ได้

เงาต้องเปิดครบสาย

renderer.shadowMap.enabled = true;
light.castShadow = true;    // เลือก light ที่รองรับเงา
object.castShadow = true;  // ตัวทอดเงา
floor.receiveShadow = true; // ตัวรับเงา
// ตรวจ shadow camera/frustum ว่าครอบทั้งตัวทอดเงาและพื้นที่รับเงา

ถ้าเงาไม่ขึ้น ให้ตรวจไฟและวัสดุที่รองรับ, flags ทั้งหมด, shadow camera และตำแหน่งจริงของแสง วัตถุ และพื้น Shadow acne คือปื้น/ริ้วเงาที่ผิวตัวเอง ซึ่งอาจต้องปรับ bias หรือ normalBias ให้เหมาะสม ปรับมากเกินทำให้เงาดูหลุดจากวัตถุได้

Background ≠ Environment

scene.background กำหนดสิ่งที่เห็นด้านหลัง ส่วน scene.environment ให้ข้อมูลแสงแวดล้อม/การสะท้อนกับวัสดุที่รองรับ การตั้งพื้นหลังเป็นสีฟ้าอย่างเดียวไม่ได้ทำให้วัตถุมีแสงฟ้าหรือสะท้อนฉากอัตโนมัติ Skybox ใช้ภาพ 6 ทิศ: ±x, ±y, ±z; Fog ลดการมองเห็นตามระยะ ไม่ใช่เงา

Perspective กับ Orthographic

Perspective ทำให้ของไกลดูเล็ก มีผลของความลึกแบบมุมมอง ส่วน Orthographic ทำให้ขนาดภาพไม่ลดเพียงเพราะวัตถุไกลขึ้น เหมาะกับแบบเทคนิค/มุมไอโซเมตริก โดย isometric เป็นการจัดมุมมองแบบหนึ่ง ไม่ใช่คำแทนกล้อง Orthographic ทุกกรณี

ตัวอย่าง API ในสไลด์บางส่วนใช้ Three.js รุ่นเก่า เช่น SphereBufferGeometry และ sRGBEncoding คู่มือนี้เน้นความหมายที่ใช้ตอบสอบ หากนำไปรันจริงควรใช้ API ให้ตรงเวอร์ชันของโครงการ

07 · โจทย์คำนวณพร้อมวิธีทำ 12 ข้อ

ลองทำก่อนเปิดเฉลย จะรู้ทันทีว่ายังติดตรงไหน

1. Lambert พร้อม normalize

N=(0,3,4), L=(0,0,2), kd=0.8, Ip=1.5 จงหา diffuse

เปิดวิธีทำทีละขั้น
① |N|=5 → N̂=(0,.6,.8); |L|=2 → L̂=(0,0,1)
② N̂·L̂=.8
③ Id=.8×1.5×max(.8,0)=.96
จุดพลาด: dot โดยไม่ normalize จะได้ 8 ซึ่งไม่ใช่ cosine

2. Phong รวม 3 พจน์

ka=.2, Ia=.3, kd=.6, Ip=1, N·L=.5, ks=.4, R·V=.5, n=4 จงหา I

เปิดวิธีทำทีละขั้น
Ambient=.2×.3=.06
Diffuse=.6×1×.5=.30
Specular=.4×1×(.5)⁴=.025
รวม=.385 ยังไม่ต้อง clamp ถ้าโจทย์ไม่ได้สั่ง

3. แสงมาจากหลังผิว

N·L=−.4, kd=.7, Ip=2, ambient=.1 จงหา ambient+diffuse

เปิดวิธีทำทีละขั้น
Diffuse=.7×2×max(−.4,0)=0
รวม=.1 ไม่ใช่ −.46 เพราะ diffuse ต้องไม่ติดลบ

4. Reflect กับเครื่องหมาย

N=(0,1,0), L=(0,1,0), V=(0,1,0) จงหา R และ specular factor เมื่อ n=8

เปิดวิธีทำทีละขั้น
Iincident=−L=(0,−1,0)
R=I−2(N·I)N=(0,−1,0)−2(−1)(0,1,0)=(0,1,0)
R·V=1 → 1⁸=1 ถ้าใช้ reflect(L,N) จะได้ทิศผิด

5. Cel quantization

d=.82, levels=3; q=floor(d×levels)/levels แล้วเพิ่ม .6 ตามตัวอย่างสไลด์

เปิดวิธีทำทีละขั้น
floor(.82×3)/3=floor(2.46)/3=2/3≈.6667
หลังบวก .6 ได้ 1.2667 ซึ่งเกิน 1 ได้ โค้ดไม่ได้ clamp ในบรรทัดนี้ อย่าฝืนตอบ 1 โดยไม่มีเงื่อนไข

6. GLSL ค่าลบและ threshold

หา fract(−2.3), floor(−2.3), step(.5,.5), smoothstep(.4,.6,.5)

เปิดวิธีทำทีละขั้น
floor(−2.3)=−3; fract=−2.3−(−3)=.7
step ที่เท่ากับ edge ได้ 1
smoothstep: u=(.5−.4)/(.6−.4)=.5 → u²(3−2u)=.5

7. Picking เมื่อ canvas มี offset

canvas left=100, top=50, width=800, height=400; คลิก client=(700,150) หา NDC

เปิดวิธีทำทีละขั้น
px=700−100=600; py=150−50=100
x=2×600/800−1=.5
y=1−2×100/400=.5
ต้องลบ offset ก่อน และต้องกลับแกน y

8. Ray เลือกด้านหน้า

ผลทางคณิตศาสตร์ได้ t=−2, 3, 7 จงเลือก hit; O=(1,0,0), D=(0,0,−1) หาตำแหน่งนั้น

เปิดวิธีทำทีละขั้น
ตัด t=−2 เพราะอยู่หลังจุดเริ่ม ray เลือกค่าบวกต่ำสุด t=3
P(3)=(1,0,0)+3(0,0,−1)=(1,0,−3)

9. LERP สเกลาร์และเวกเตอร์

a=10,b=30,t=.35; A=(0,2,4),B=(10,6,0),t=.25

เปิดวิธีทำทีละขั้น
สเกลาร์ 10+(30−10)×.35=17
เวกเตอร์=(0+10×.25, 2+4×.25, 4−4×.25)=(2.5,3,3)

10. LERP ปัจจุบันทุกเฟรม

เริ่ม x=0 เป้า 10 ใช้ x=lerp(x,10,.2) สองเฟรม จงหาค่า

เปิดวิธีทำทีละขั้น
เฟรม 1: 0+(10−0)×.2=2
เฟรม 2: 2+(10−2)×.2=3.6 ไม่ใช่ 4
หลัง n เฟรม xₙ=10(1−.8ⁿ) ระยะห่างลดแบบเรขาคณิต

11. Quadratic Bezier

P0=(0,0),P1=(2,4),P2=(4,0),t=.5 หาจุด B

เปิดวิธีทำทีละขั้น
น้ำหนัก (1−t)²=.25, 2(1−t)t=.5, t²=.25
B=.25(0,0)+.5(2,4)+.25(4,0)=(2,2)
เส้นไม่ได้ผ่าน P1=(2,4) ณ กึ่งกลาง

12. Cubic Bezier และ easing

P0=0,P1=0,P2=10,P3=10 ที่ t=.25; เปรียบเทียบ linear 0→10

เปิดวิธีทำทีละขั้น
น้ำหนัก .421875,.421875,.140625,.015625
B=10(.140625+.015625)=1.5625
Linear=2.5; สูตร cubic นี้เท่ากับ 10(3t²−2t³) เริ่มช้ากว่า linear

09 · อัตนัยและโจทย์อ่านโค้ด 12 ข้อ

ลองเขียนเป็นประโยคก่อนดูแนวตอบ · มีเกณฑ์ให้ตรวจตัวเอง

1. อธิบาย Material 4 แบบและเลือกใช้ให้ตรงงาน

งานมีป้ายสีคงที่ ผนังด้าน ลูกบอลมัน และรูปปั้นโลหะ จงเลือก Basic/Lambert/Phong/Standard พร้อมเหตุผล

แนวตอบและเกณฑ์ตรวจ

ป้ายใช้ Basic เพราะสีไม่ต้องพึ่งแสง; ผนังใช้ Lambert เพราะต้องการ diffuse; ลูกบอลใช้ Phong เพื่อมี specular และปรับ shininess; รูปปั้นโลหะใช้ Standard/PBR โดย metalness สูงและ roughness ตามความเรียบ พร้อม environment/ไฟที่เหมาะสม

4 คะแนน: เลือกครบ 4 แบบและอธิบายคุณสมบัติแบบละ 1 คะแนน

2. เขียนสมการและนิยามเวกเตอร์

เขียน Lambert กับ Phong ระบุ N,L,V,R และอธิบายว่าเหตุใด diffuse ไม่ขึ้นกับกล้อง แต่ specular ขึ้น

แนวตอบและเกณฑ์ตรวจ

Lambert=kd Ip max(N·L,0); Phong เพิ่ม ka Ia และ ks Ip max(R·V,0)^n โดย N คือ normal, L จากผิวไปไฟ, V จากผิวไปกล้อง, R=reflect(−L,N) ทุกเวกเตอร์เป็นหน่วยและอยู่ space เดียวกัน Lambert ไม่มี V จึงไม่ขึ้นกับทิศกล้อง ส่วน specular มี R·V

6 คะแนน: สูตร diffuse 1, สูตรรวม 1, นิยามเวกเตอร์ 2, normalize/space 1, เหตุผลเรื่องกล้อง 1

3. คำนวณแสงเต็มข้อ

ka=.1,Ia=.5,kd=.8,Ip=2,N·L=.5,ks=.2,R·V=.5,n=2 คำนวณแยก 3 พจน์และผลรวม

แนวตอบและเกณฑ์ตรวจ

Ambient=.05; Diffuse=.8×2×.5=.8; Specular=.2×2×.25=.1; รวม=.95 โดยค่าที่กำหนดเป็น scalar และด้านนี้รับแสง

4 คะแนน: พจน์ละ 1 และผลรวม 1

4. จับผิด Shader 3 จุด

โค้ด: N=normalMatrix*normal; L=lightWorld-posWorld; R=reflect(L,N); s=pow(dot(R,V),16.0); จงอธิบายจุดผิดหลักและแนวแก้

แนวตอบและเกณฑ์ตรวจ

หนึ่ง N เป็น View แต่ L เป็น World ต้องแปลง space ให้ตรงและ normalize; สอง L นิยามไปหาไฟ จึงต้อง reflect(−L,N); สาม ต้อง max(dot(R,V),0) ก่อน pow และ V ต้องเป็นหน่วยใน space เดียวกัน เพิ่มการปิด specular เมื่อ N·L≤0 ตามโมเดลผิวด้านเดียว

6 คะแนน: space 2, normalize 1, เครื่องหมาย reflect 1, max ก่อน pow 1, นิยาม V/ด้านรับแสง 1

5. เล่าขั้นตอน Picking แบบไม่ข้ามขั้น

canvas left=50,top=20,width=600,height=300 คลิก client=(350,95) หา NDC แล้วอธิบายการเลือก

แนวตอบและเกณฑ์ตรวจ

local=(300,75); NDC=(0,.5); ส่ง pointer กับ camera เข้า setFromCamera → intersectObjects รายการเป้าหมาย → ตรวจ hits.length → เลือก hits[0].object; หากเป็น Group และต้องตรวจลูกให้ recursive=true; hit อาจเป็น mesh ลูก

5 คะแนน: local 1, NDC 1, ray 1, intersect 1, ตรวจ hit/เลือกใกล้สุด 1

6. เปรียบเทียบ LERP สองลักษณะ

ระหว่าง lerp(start,end,t) โดย start/end คงที่ กับ lerp(current,end,.1) ทุกเฟรม ต่างกันอย่างไร?

แนวตอบและเกณฑ์ตรวจ

แบบแรกเมื่อ t เพิ่มเชิงเส้น 0→1 จะเดินทางเชิงเส้นและถึงปลายที่ t=1 ส่วนแบบสองลดระยะห่างที่เหลือลง 10% ทุกเฟรม จึงช้าลงใกล้ปลายและไม่ถึงปลายพอดีในจำนวนเฟรมจำกัดทางคณิตศาสตร์; ถ้าต้องการลดผล frame rate ใช้ alpha=1−exp(−speed×dt)

4 คะแนน: คง start 1, พฤติกรรมแบบแรก 1, แบบสอง 1, ผลเรื่อง frame rate 1

7. วิเคราะห์คลื่นใน Vertex Shader

pos.y += sin(pos.x*5.0 + uTime*3.0)*.1; บอกแกนที่ขยับ amplitude ความถี่และเวลาต่อรอบ โดย uTime เป็นวินาที

แนวตอบและเกณฑ์ตรวจ

ขยับแกน y ใน local space; amplitude=.1; spatial angular frequency=5, wavelength=2π/5; angular speed=3 rad/s, period=2π/3 วินาที เปลี่ยน multiplier ของเวลาเพื่อปรับความเร็ว ไม่ใช่ amplitude และต้องมี vertices พอให้รูปคลื่นละเอียด

5 คะแนน: แกน 1, amplitude 1, spatial frequency/wavelength 1, speed/period 1, density 1

8. วาดและอธิบายกราฟ Easing

อธิบาย Linear, Ease In, Ease Out, Ease InOut ด้วยกราฟค่า–เวลา และยกตัวอย่างการเคลื่อนไหว

แนวตอบและเกณฑ์ตรวจ

Linear ความชันคงที่; Ease In เริ่มราบแล้วชันขึ้น เช่นวัตถุเริ่มเร่ง; Ease Out เริ่มชันแล้วราบ เช่นกล้องชะลอเข้าจุดหมาย; InOut ราบต้น ชันกลาง ราบท้าย เช่นประตูเปิดนุ่มทั้งต้นปลาย ต้องระบุแกนเวลาและค่า และอธิบายความเร็วจากความชัน ไม่ใช่ความสูงกราฟ

5 คะแนน: รูปร่างครบ 4 แบบ 4, อธิบายความชันและแกน 1

9. Bezier แบบคำนวณ

Cubic P0=(0,0),P1=(0,4),P2=(4,4),P3=(4,0) ที่ t=.5 จงหา B และตอบว่าจุดควบคุมกลางต้องอยู่บน curve หรือไม่

แนวตอบและเกณฑ์ตรวจ

น้ำหนัก 1/8,3/8,3/8,1/8 → x=0+0+1.5+.5=2; y=0+1.5+1.5+0=3 จึงได้ (2,3); จุดควบคุมกลางไม่จำเป็นต้องอยู่บน curve และ t เท่ากันไม่รับประกันระยะเคลื่อนที่เท่ากัน

4 คะแนน: น้ำหนัก 1, คำนวณพิกัด 2, ความหมาย control points 1

10. ออกแบบ Cel พร้อม outline

อธิบาย diffuse แบบเป็นขั้น specular แบบคม และการสร้างขอบดำตามตัวอย่างเรียน

แนวตอบและเกณฑ์ตรวจ

คำนวณ d=max(dot(N,L),0) แล้ว quantize เช่น floor(d*3)/3; ใช้ step(edge,specular) หรือ smoothstep สำหรับไฮไลต์; สร้าง mesh ชั้นนอกขยายตาม normal ใช้สีเข้มและ BackSide ให้เห็นขอบ โดย deformation ควรตรงกับ mesh หลัก; สูตร floor นี้ที่ d=1 ให้ระดับ 1 เพิ่มจากค่าภายในช่วง

4 คะแนน: diffuse 1, quantize 1, highlight 1, inverted hull 1

11. วิเคราะห์เงาไม่ขึ้น

มีไฟหนึ่งดวงกับลูกบอลบนพื้น เปิด ball.castShadow แล้ว แต่ไม่เห็นเงา ให้เรียงจุดตรวจหลัก

4 คะแนน: renderer 1, light 1, receiver/material 1, camera/ตำแหน่ง 1

12. ออกแบบประตูให้หมุนถูกบานพับ

ประตูปิด 0° เปิด 90° ใน 2 วินาที จงอธิบาย pivot, keyframes, interpolation และมุมเวลา .5 วินาทีแบบ linear

แนวตอบและเกณฑ์ตรวจ

ตั้ง pivot ที่ขอบบานพับ; keyframe rotation 0° ตอนเริ่มและ 90° ที่ 2 วินาที; linear t=.5/2=.25 → 22.5° ถ้าต้องการเริ่มจบช้าใช้ Bezier/ease-in-out และดูความชันใน F-Curve; Dope Sheet ใช้เลื่อน timing ของ keys

5 คะแนน: pivot 1, keys 1, t/มุม 1, easing 1, เครื่องมือ 1

10 · ชีตสุดท้ายก่อนเข้าห้องสอบ

ทวนให้ตอบได้โดยไม่มอง · เน้นความผิดที่เสียคะแนนง่าย

Material / Shader

  • Basic = unlit
  • Lambert = diffuse
  • Phong = ambient + diffuse + specular
  • Standard = PBR, metalness/roughness
  • Vertex: gl_Position; Fragment: สี fragment
  • attribute ต่อ vertex; uniform จากภายนอก; varying เชื่อม stages

สูตรต้องเขียนได้

  • clip = P × V × M × position
  • Id = kd Ip max(N·L,0)
  • Is = ks Ip max(R·V,0)ⁿ
  • R = reflect(−L,N)
  • lerp = a+(b−a)t
  • Ray: O+tD, เลือก t≥0 ที่น้อยสุด

Picking / Animation

  • NDC x=2px/w−1; y=1−2py/h
  • ลบ offset canvas ก่อน normalize
  • setFromCamera → intersect → ตรวจ hit → hits[0]
  • Linear = ความชันคงที่
  • Ease In ช้า→เร็ว; Out เร็ว→ช้า
  • Cubic Bezier = 4 จุด; จุดกลางไม่ต้องอยู่บนเส้น

10 จุดห้ามพลาด

  1. Normalize ก่อนใช้ dot เป็น cosine
  2. เวกเตอร์ต้องอยู่ space เดียวกัน
  3. max ก่อน pow ไม่ใช่หลัง pow
  4. shininess สูง = ไฮไลต์แคบ
  5. step เท่าขอบให้ 1
  6. floor ค่าลบปัดลงจริง
  7. กลับแกน y ตอนทำ NDC
  8. เช็ก hit ก่อน .object
  9. LERP current ซ้ำไม่ใช่ความเร็วคงที่
  10. ความเร็วดูความชัน ไม่ใช่ความสูง
